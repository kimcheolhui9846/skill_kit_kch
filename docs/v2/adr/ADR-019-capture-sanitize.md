# ADR-019: capture 정제 규칙
- 상태: 승인(2026-11-05)
- 관련: D-19, REQ-USER-003/004
- 날짜: 2026-11-05

## 배경
`capture`는 이 PC의 `~/.codex`, `~/.claude`에서 이식할 설정을 레포의 `user/`로 가져온다. 그런데 이 PC에는 가져오면 안 되는 것이 함께 있다(global-inventory):
- auth 파일
- context7 API 키 헤더
- projects trust 경로 12개
- 세션, sqlite

## 선택지
1. 허용 목록: 가져올 키와 파일만 명시하고 나머지는 모두 버린다.
2. 차단 목록: 위험한 키만 지운다.

## 결정
**선택지 1(허용 목록)에 최종 토큰 스캔을 더한다(이중 안전장치).**
- 허용 목록은 `user/capture-allowlist.json`에 둔다.
- 경로는 `${HOME}`으로 템플릿화한다.
- MCP 헤더·env는 **이름만** 남기고, 값은 `${ENV:NAME}` 자리표시자로 바꾼다.
- 기본은 dry-run이고, `--write`를 줘야 쓴다.

## 근거
차단 목록 방식에서는 새 키가 생기면 자동으로 새어 나간다. 허용 목록 방식에서는 새 키를 기본으로 버린다.

## 결과와 위험
- 테스트 V-20: `user/` 전체의 비밀값 스캔.
- 테스트 V-21: capture → install 왕복.
- fixture에 가짜 토큰을 심어 반드시 걸리는지 확인한다.
- 위험: 허용한 키의 값 안에 비밀값이 들어 있을 수 있다 → 마지막 단계의 스캐너가 차단한다.

## 되돌리는 방법
`user/`의 파일을 지운다. 비밀값이 git 이력에 남지 않도록 커밋 전에 검사한다.
