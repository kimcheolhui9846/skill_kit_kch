# 설계: V2 지시서 보강 (사용자 목록 우선 통합, 출시 점검 스킬, 전역 설정 재현)

- 날짜: 2026-11-05
- 상태: 승인(검토자, 2026-11-05)
- 규범 문서: `docs/v2/00_ADDENDUM.md` (요구사항 원문은 그쪽에만 둔다)

## 배경

`docs/v2/00_PROMPT.md`(V2 지시서)는 이 키트를 Codex·Claude Code 공용의 **작업 공간 설치** 키트로
확장한다. 검토자는 여기에 세 가지를 더 원한다.

1. 직접 고른 오픈소스 스킬·MCP 목록(49개. 원본 번호가 20부터 다시 시작해 39개로 보이지만 실제로는 49개)을 우선 채택하고, 레포 기존 스킬과 겹치면 목록 쪽을
   남기고 레포를 정리한다.
2. 웹 출시 전 법적·접근성 점검 20개 항목을 스킬로 만든다.
3. 이 PC의 Codex·Claude 전역 설정을 레포에 정리해 어느 환경에서든 불러와 적용한다.

## 검토자 결정

| 질문 | 결정 |
|---|---|
| 진행 방식 | 지시서에 요구사항으로 편입하고 Phase 1부터 지시서 순서대로 진행 |
| 전역 설정 원본 | 이 PC의 `~/.codex`, `~/.claude`. 바탕화면 `프롬포트 설정/`은 참고만 |
| 중복 처리 | 새 경로(standard, claude/both)는 사용자 목록 버전, 기존 restricted 경로는 기존 8개 스킬 보존 |

## 설계 요지

- **원문 불변 + 보강 문서.** 지시서 원문은 해시와 함께 그대로 복사하고, 바뀌는 점은
  `00_ADDENDUM.md`에만 쓴다. 원문 REQ와 충돌하는 곳(REQ-SAFE-008)은 보강 문서에서 명시적으로
  바꾼다. 이렇게 하면 무엇이 원래 요구이고 무엇이 추가인지 추적할 수 있다.
- **경로 분리로 "목록 우선"과 하위 호환을 함께 만족.** 기존 호출은 해커톤 제한 환경용이고 골든
  테스트로 고정된다. 목록 우선 규칙은 새 경로에만 적용한다(REQ-SRC-007).
- **전역 적용은 별도 범위(`--scope user`).** 기본 `project` 범위의 안전 보장(전역 무변경)은 그대로
  두고, 전역 쓰기는 plan → 확인 → 백업 → 소유 구간만 수정의 절차를 거친다(REQ-USER-002).
  개발 중에는 HOME을 임시 디렉터리로 바꿔 테스트하므로 원문 R-06과 충돌하지 않는다.
- **비밀값 차단을 테스트로 강제.** `capture`의 정제 규칙과 `user/` 스캔 테스트(REQ-USER-004)로
  인증 파일·토큰·신뢰 경로가 레포에 들어가지 않게 한다.
- **추측 금지.** 목록의 이름 중 저장소를 하나로 정할 수 없는 것은 `UNRESOLVED`로 두고 묻는다.
  목록에 있어도 라이선스·버전 고정·원격 설치 스크립트 규칙은 면제하지 않는다.

## 대안과 기각 이유

- **목록 버전으로 완전 교체:** 해커톤 경로의 설치 결과가 바뀌어 REQ-COMPAT-002와 골든 테스트를
  폐기해야 한다. 검토자가 기각.
- **전역 설정을 별도 dotfiles 레포로 분리:** 스킬·MCP 카탈로그, 감사, 백업 로직을 중복 구현해야
  한다. 같은 실행기를 범위만 바꿔 재사용하는 편이 단순하다.
- **원문 지시서를 직접 수정:** 무엇이 추가 요구인지 추적하기 어렵다.

## 범위 밖

- 실제 전역 설정 적용과 외부 리소스 반입은 각 Phase의 승인 게이트를 거친 뒤에 한다.
- 이 문서는 구현 계획이 아니다. 계획은 Phase 1 산출물 `docs/v2/03_PLAN.md`에서 만든다.
